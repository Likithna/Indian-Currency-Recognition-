# Currency Recognition System
**Samsung Innovation Campus AIML Capstone Project**

A system that identifies the denomination of an Indian banknote from a photo
(CNN, transfer learning) and displays the official RBI security-feature
checklist for that note (anti-counterfeit information).

---

## Setting up the RBI Guidelines Assistant (Gemini API)

The chatbot works out of the box in a limited offline mode (a small
curated FAQ), but for real, general-purpose answers you need a free
Gemini API key:

1. Go to [aistudio.google.com/apikey](https://aistudio.google.com/apikey),
   sign in with a Google account, and create a key. No credit card
   required — Google's Gemini API has a genuinely free tier for the
   Flash model family.
2. **Running locally:** copy `.streamlit/secrets.toml.example` to
   `.streamlit/secrets.toml` and paste your key in:
   ```toml
   GEMINI_API_KEY = "your-real-key-here"
   ```
   This file is already in `.gitignore` — never commit a real key to a
   public GitHub repo.
3. **Deploying on Streamlit Community Cloud:** don't upload
   `secrets.toml` at all. Instead, go to your app's dashboard ->
   **Settings -> Secrets** and paste the same `GEMINI_API_KEY = "..."`
   line there.
4. Without a key configured, the chatbot still works — it just falls
   back to the small offline FAQ, and the panel shows an "Offline mode"
   indicator so it's clear which path answered. This means your demo
   never breaks even if the API is unreachable or you hit a rate limit.

## 2. How the system actually works (read this before your viva/demo)

The assignment asks for a system that "generates denomination and
anti-counterfeit information." There are two honestly different jobs
bundled in that sentence, and it matters that you can explain the
difference to your professor:

- **Denomination classification — this is genuine machine learning.**
  A MobileNetV2 CNN is fine-tuned on the Kaggle *Indian Currency Banknotes
  Dataset* to recognise which denomination (₹10/20/50/100/200/500/2000) is
  in a photo. This is a real, trained, evaluated model.

- **Anti-counterfeit information — this is a rule-based lookup, on
  purpose.** No public dataset of confirmed counterfeit Indian notes
  exists (for good reason), so there is nothing to train a "real vs. fake"
  classifier on. Instead, once the CNN identifies the denomination, the
  app looks up the **official RBI security features** for that note —
  watermark, security thread, latent image, identification mark shape,
  etc. — the same checklist RBI itself publishes for the public to verify
  notes manually. This is the same design used by RBI's own MANI
  (Mobile Aided Note Identifier) app.

Being upfront about this distinction in your report will make your project
*stronger*, not weaker — it shows you understood the limits of your data
instead of quietly overclaiming what the model does.

### Two more pieces worth highlighting in your report/viva

- **Out-of-distribution rejection.** The model was only ever trained on 11
  currency classes, so by construction it will always pick one of them —
  even for a photo of an airplane. `app.py` gates the result behind a
  confidence threshold (`OOD_CONFIDENCE_THRESHOLD`, default 70%): if the
  top prediction doesn't clear it, the app shows "Not Recognized as an
  Indian Currency Note" instead of a wrong denomination. This is a classic
  softmax-confidence heuristic — simple, has real limits (a model can
  occasionally be confidently wrong), but is a legitimate, explainable
  first line of defense and a good thing to name as a deliberate design
  choice.
- **RBI Guidelines Assistant (`rbi_chatbot.py`).** A chatbot on the right
  side of the app answers questions about RBI rules, currency guidelines,
  and general knowledge on any topic. It calls Google's Gemini API
  (free tier) for real, flexible answers, and automatically falls back to
  a small offline FAQ system (TF-IDF + cosine similarity over a curated
  Q&A knowledge base) if no API key is configured or a request fails —
  worth mentioning in your report as a deliberate "graceful degradation"
  design choice: the app stays usable even without internet access or an
  API key.

## 3. Part A — Train the model (Google Colab)

1. Go to [colab.research.google.com](https://colab.research.google.com),
   sign in, and upload `training_notebook.ipynb` (`File -> Upload notebook`).
2. `Runtime -> Change runtime type -> T4 GPU` (free tier), then `Save`.
3. Get a Kaggle API token: [kaggle.com/settings](https://www.kaggle.com/settings)
   -> **API Tokens** tab -> **Create New Token**. Kaggle now shows a single
   token string (`KGAT_...`) rather than a `kaggle.json` file to download —
   copy it, you won't be able to view it again after closing the dialog.
4. Run the notebook cells **from top to bottom, one at a time**. Read each
   markdown cell above a code cell before running it — that's the
   explanation of *why* that step exists.
5. When you hit the dataset-download step, the notebook downloads
   `yashdogra/2000-notes` automatically using your Kaggle key.
6. The EDA step (Step 3) prints the actual folder structure. If the class
   folders turn out to be nested differently than expected, the notebook
   tells you exactly which variable to adjust (`IMAGE_ROOT`) — this is
   normal, real datasets are rarely perfectly tidy.
7. Training happens in two phases (frozen base, then fine-tuning) — this
   will take anywhere from 10–40 minutes total on the free GPU depending
   on dataset size.
8. The last cells save and download `currency_model.keras` and
   `class_names.json`. **Save both into this same project folder.**

**If your validation/test accuracy is disappointing:** it's very likely
class imbalance (some denominations have far fewer sample images) or too
few training images overall for 7 classes — both are legitimate, common
findings worth discussing in your report, not something you did wrong.
Options to try: `class_weight` in `model.fit()`, more aggressive
augmentation, or increasing `FINE_TUNE_AT`'s unfrozen layer count.

## 4. Part B — Run the app locally

Once `currency_model.keras` and `class_names.json` are in this folder:

```bash
pip install -r requirements.txt
streamlit run app.py
```

This opens the app in your browser (usually `http://localhost:8501`).
Upload a photo of a note and confirm the prediction + security-feature
checklist both appear correctly before moving on to deployment.

## 5. Part C — Deploy it for free (Streamlit Community Cloud)

1. Create a **public GitHub repository** and push everything in this
   folder to it, including `currency_model.keras` and `class_names.json`
   (if the model file is over 100 MB, use
   [Git LFS](https://git-lfs.com) — MobileNetV2-based models are usually
   well under that).
2. Go to [share.streamlit.io](https://share.streamlit.io), sign in with
   GitHub, click **New app**, and point it at your repo and `app.py`.
3. Click **Deploy**. In a couple of minutes you'll have a public URL you
   can put directly in your report and share with your professor.

## 6. What to put in your project report / presentation

- **Problem statement** — denomination recognition + accessible security
  info, framed around the assignment brief.
- **Dataset** — Kaggle *Indian Currency Banknotes Dataset*
  (yashdogra/2000-notes), class counts from your EDA bar chart, and a
  sample-image grid.
- **Methodology** — transfer learning with MobileNetV2, why transfer
  learning was chosen over training from scratch, the two-phase
  (freeze → fine-tune) training strategy, and the augmentation choices
  (and *why* horizontal flip was deliberately excluded — that's a nice
  detail that shows domain understanding).
- **Results** — final test accuracy, the confusion matrix, and a couple
  of classes that were most confused with each other (usually visually
  similar denominations).
- **The security-feature module** — explicitly explain the "lookup table,
  not a forgery detector" design decision from Section 2 above. This is
  the single most important thing to get across clearly.
- **Deployment** — a screenshot of the live Streamlit app with a
  prediction and its checklist, plus the public URL.
- **Limitations & future work** — dataset size, no real counterfeit
  detection (and why), possible next steps (larger dataset, on-device
  TFLite version, multilingual UI given the note's own 15-language panel).
